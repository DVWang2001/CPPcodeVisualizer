## 1. 目標（使用者原話的整理）

- 建立「錯誤視覺化」領域：收集學生常犯的程式錯誤（典型如整數溢位、指標超界），教學時執行這些程式，讓學生看見錯誤發生的過程。
- 由專案右側欄顯示「為什麼錯」。
- 最終希望在教案庫看到對應的錯誤視覺化。

## 2. 文獻與典型錯誤（已完成，見 `docs/superpowers/research/2026-11-05-error-visualization-research.md`）

- 已有研究可模仿：OGRE（記憶體 3D 視覺化）、Python Tutor（含 C/C++ 越界視覺化）、Sasano（以 GDB 視覺化 return address 覆寫）、Michigan Tech（整數溢位視覺化）、dcc（白話錯誤訊息）。

## 5. 引擎的事實（已由 README 與程式碼確認）

- 引擎是**瀏覽器內的 C++ 編譯執行器**（wasm），取代已移除的伺服器 GDB（2026-10-05 設計）。
- `pipeline.worker.js`：只負責編譯側（PCH → AST → 插樁 → 編譯 → 連結 → 解碼軌跡），不執行學生程式，不連網。連結參數 `LINK_FLAGS` 定義於此。
- `exec.worker.js`：每次執行一個程式後結束，唯一對外通道是受限的 WASI import。
- 連結參數 `--stack-first` 讓棧在低位址、一路長到位址 0 附近，所以 **空指標（0x00000000）落在可讀的棧底，不會 trap**。
- 軌跡格式（fd 3）不含位址欄位。`trace.js` 會拒絕未知欄位。
- 位址是 `localgdb/model.js:377-386` 的 `varAddr` 算出的**假位址**（`0x7ffe00000000 + …`），不是 wasm 記憶體的真實位址。
- 指標只支援指向已追蹤的算術變數；不支援堆積（`new`）、指向陣列或結構成員的指標、`char*`、指標算術。
- 軌跡只追蹤有名字的純量變數，**結構成員與堆積不在軌跡裡**。

## 6. 已做出的決定

- **不追求引擎崩潰**：不改 `pipeline.worker.js` 的連結參數，不做守衛區或偏移量技巧。空指標案例顯示引擎實際結果（讀到 0），並在右側欄說明環境差異。（記憶：`project_error_viz_no_crash_goal.md`）
- **環境差異要明說**：重複釋放、迭代器失效、空指標等，在右側欄註明「與原生 Linux 不同，同一錯誤的表現可能不同」。
- **位址只用相對偏移**：結構內偏移（例如 `b+16`）由 C++ 佈局決定，與環境無關，可以使用。絕對位址與堆積位址不畫出來。
- **圖一律標示為示意圖**：記憶體圖是依程式結構推算的，不是引擎的記憶體傾印。
