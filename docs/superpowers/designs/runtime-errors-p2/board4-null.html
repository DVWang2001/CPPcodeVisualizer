透過空指標存取成員 （null pointer）

21 std::cout << "值：" << cur->val << "，下一個值：" << cur->next->val << std::endl;
1發生了什麼
cur->next是 nullptr->val✕ 沒有節點可以讀

第 2 圈時 cur 指向 b。b 是最後一個節點，b.next 是 nullptr（沒有指向任何節點），所以 cur->next->val 沒有東西可以讀。

這一行已經印出「值：20，下一個值：」，印到一半就停了。

2值從哪裡來
b.next = nullptr第 16 行 Node b{20, nullptr};　跳到那一步
cur 指向 b第 1 圈結束時，第 22 行 cur = cur->next;　跳到那一步
3怎麼改

讀 cur->next->val 之前，先確認 cur->next 不是 nullptr。

std::cout << "值：" << cur->val;
if (cur->next != nullptr) {
    std::cout << "，下一個值："
              << cur->next->val;
}
std::cout << std::endl;
和原生 Linux 比較：g++ 編譯的程式會在這一行崩潰（Segmentation fault），而且只印出第 1 行：第 2 行印到一半的字還在緩衝區，來不及印出來。
原始錯誤訊息（第 21 行第 65 個字）

現在的軌跡只記得指標是不是 nullptr（是：0；不是："<ptr>"），不記得指向誰。這個例子的 cur 指向具名變數 b，軌跡一樣只記成 "<ptr>"。要畫出左邊卡片裡的箭頭，引擎得多記指標的位址，再對到變數。

實作時要注意（從這次的實測資料看到的）

  • 錯誤紀錄的欄位是 UTF-8 的位元組位置：第 21 行 col 81，換成字元是第 65 個字，正好是 cur->next->val 的 val。行裡有中文時一定要換算，不然底線會畫錯地方。
  • 指標箭頭：vg.h 只有「指向已登記變數的指標變數」會記下指向誰（__vgp）；struct 變數、struct 裡的指標欄位、new 出來的節點都不在內（engine/localgdb/types.js 的註解）。
