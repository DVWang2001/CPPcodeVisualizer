對空的 stack 呼叫 top() （empty container）

 7   cout << s.top() << endl;
1發生了什麼
s.top()↓
空的
s　size = 0

top() 要拿 stack 最上面的元素，可是 s 裡一個元素都沒有，沒有東西可以拿。

2值從哪裡來
s 變成空的第 6 行 s.pop() 拿走了最後一個元素（1）　跳到那一步
3怎麼改

拿之前先確認 stack 不是空的。

if (!s.empty()) {
    cout << s.top() << endl;
}
和原生 Linux 比較：g++ 編譯的程式會在這一行崩潰（Segmentation fault）。
原始錯誤訊息（第 7 行）
deque::back called on an empty deque

stack 預設用 deque 存放元素，top() 會去呼叫 deque 的 back()，所以訊息寫的是 deque::back。

同一種錯誤、其他容器的畫面（也是實測；設計稿說明，不在面板裡）
v.back()
空的
v　size = 0
第 5 行 cout << v.back()；v 從第 4 行宣告起就是空的。
原生 g++：崩潰（Segmentation fault）。
訊息：back() called on an empty vector
q.front()
front
空的
back
q　size = 0
第 5 行 cout << q.front()；q 從第 4 行宣告起就是空的。
原生 g++：不會報錯，印出 0（讀到沒有意義的值）。
訊息：deque::front called on an empty deque

實作時要注意（從這次的實測資料看到的）

  • libc++ 的訊息寫的是底層的 deque／vector 函式（deque::back），面板要換成學生寫的那個呼叫（s.top()）：用錯誤的行號在原始碼裡找容器的成員呼叫，再用軌跡那一步的變數確認它是空的。
  • 「值從哪裡來」找容器最後一次變空的那一步：stack 是第 6 行的 pop()；vector 和 queue 是第 4 行的宣告。
