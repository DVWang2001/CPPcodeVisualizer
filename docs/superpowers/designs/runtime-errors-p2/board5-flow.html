家族 4・函式與流程程式在這裡結束

函式走到結尾都沒有 return （missing return）

 6 }          // int sign(int x) 的結尾
1發生了什麼
3int sign(int x) {x = 0 4 if (x > 0) return 1;0 > 0 不成立 5 if (x < 0) return -1;0 < 0 不成立 6}到了結尾，沒有 return

sign(0) 依序走過第 4、5 行，兩個 if 都不成立，兩個 return 都沒有執行，就走到第 6 行的 }。int 函式結束前一定要 return 一個值，這裡沒有，所以 sign(0) 沒有答案。

2值從哪裡來
x = 0第 8 行 sign(0) 傳進來的　跳到那一步
3怎麼改

補上 x 等於 0 的情況。

int sign(int x) {
  if (x > 0) return 1;
  if (x < 0) return -1;
  return 0;   // x == 0
}
和原生 Linux 比較：g++ 編譯的程式也在這裡中止（Illegal instruction）。g++ 編譯時其實已經警告：control reaches end of non-void function（第 6 行）。
原始錯誤訊息（第 3 行第 5 欄）
execution reached the end of a value-returning function without returning a value

錯誤紀錄的位置是函式名稱 sign（第 3 行）；軌跡的最後一步在第 6 行的 }。

f 的每一層都再呼叫 f(n − 1)。函式裡沒有「不呼叫自己就 return」的路，所以永遠停不下來；呼叫到第 62128 層時，堆疊空間用完了。

2值從哪裡來
第一次呼叫 f(3)第 7 行 cout << f(3)　跳到那一步
3怎麼改

加上停止條件：n 到 0 時直接 return，不再呼叫自己。

int f(int n) {
  if (n == 0) return 0;
  return f(n - 1) + 1;
}
和原生 Linux 比較：g++ 編譯的程式也會崩潰（Segmentation fault）。
原始錯誤訊息（引擎回報）
host call stack exhausted (recursion too deep)

這種錯誤沒有錯誤紀錄（runtimeErrors 是空的），是引擎回報堆疊用完（stack-overflow）。

實作時要注意（從這次的實測資料看到的）

  • 缺 return 的錯誤紀錄位置是函式名稱（第 3 行第 5 欄）；學生要看的是第 6 行的 }，也就是軌跡的最後一步，g++ 的警告也指這一行。
  • 無窮遞迴沒有錯誤紀錄，只有 exit 的 stack-overflow；塔上每一層的參數從軌跡取。62128 層是 lab-david 上用 Node 跑出來的，瀏覽器裡的層數會不同，要另外量。
  • 「函式裡沒有不呼叫自己的 return」可以從程式結構判斷。如果有停止條件、只是一直沒成立，第一段的句子要改成「停止條件 n == 0 一直沒有成立」。

要請你決定

  • 缺 return 時，編輯器要標紅哪一行？建議第 6 行的 }；錯誤紀錄記的是第 3 行。
  • 堆疊用完時，怎麼分辨學生的錯和瀏覽器引擎的限制（後者要用「這不是程式的錯」那種標題）？建議：只有「函式裡沒有不呼叫自己的 return」才直接說是無窮遞迴；其他情況用中性的標題，兩種可能都列出來。
