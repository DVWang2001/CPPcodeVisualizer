# 計畫：停在某行時，顯示「執行該行之後」的結果

狀態：**草案，待使用者核准**。未實作。
日期：2026-11-05

## 0. 目標與定義

**目標**：程式停在第 L 行（該行尚未執行）時，同時顯示「執行完第 L 行之後」的結果，讓學生看到這一行做了什麼。

**「結果」的定義（待你決定，見第 6 節）**，建議包含兩部分：
1. **變數變化**：該行執行後，哪些變數的值改變了，從什麼值變成什麼值。
2. **輸出**：該行執行時，程式在 stdout / stderr 印出了什麼。

## 1. 現況（已確認的事實）

| 項目 | 現況 | 來源 |
|---|---|---|
| 停駐點位置 | 探針放在 GDB 會停的位置，記錄的是「該行尚未執行」的狀態 | `gdbgui/static/engine/README.md` 的 Stop semantics |
| 連續同行合併 | 同一函式、同一次啟動中，連續同行的記錄只保留第一筆 | 同上 |
| 軌跡內容 | 每筆記錄含行號、函式、深度、frame、變數名、**變化的值**（差量編碼） | README 的 Trace format |
| 軌跡通道 | WASI fd 3，與 stdout / stderr 分開 | `exec.worker.js`、README |
| 輸出交付 | stdout / stderr 在程式結束後**一次**送到前端，不與步驟交錯 | `localgdb/session.js:552-557` |
| 結構成員與堆積 | 不在軌跡中 | 引擎文件，pointer 章節 |

**由此得出的關鍵限制**：
- 要知道「第 L 行執行後」的狀態，需要找到**該行之後的下一筆記錄**，而不是該行本身的記錄。
- 輸出目前與步驟分開送出，無法知道某段輸出是哪一行印的。

## 2. 核心設計

### 2.1 變數變化（後狀態）

對第 k 筆停駐點（行 L）：找出同一 frame、深度不深於當前的下一筆記錄，它的狀態即為「該行執行後」的狀態。差量比較兩者即得變化。

需處理的情況：
- **呼叫使用者函式的行**：中間的記錄來自被呼叫者（深度較深），要跳過，取回到同一 frame 的那一筆。
- **return 行**：後狀態是呼叫者的下一個停駐點，回傳值以 `result` 慣例取得（見教案規則 §1.2）。
- **最後一行 / `}`**：後狀態是函式結束或程式結束。
- **trap（如 double free、記憶體錯誤）**：該行沒有後狀態，改顯示「該行執行時發生的錯誤」。
- **迴圈**：同一行的重複執行是不同的步，各自算後狀態。

### 2.2 輸出歸屬（最困難的部分）

**問題**：輸出在程式結束後才交付，且與 fd 3 的軌跡不交錯。要知道某段輸出屬於哪一行，需要「輸出位元組偏移」與「步驟」對齊。

**方案 X（建議）**：在宿主端（`exec.worker.js` 的 `fd_write`）為每筆 fd 3 的記錄蓋上「當時 stdout 已寫入的位元組數」。宿主是按順序處理 fd_write 的，因此這個數字是確定的，不依賴學生程式。
- 這個戳記由宿主產生，不是學生寫的。但記錄內容仍由程式產生，風險見第 5 節。

**已知陷阱**：C++ 的 `std::cout` 在非終端機時是**全緩衝**，`cout << x` 不加 `endl` 時，輸出可能在很久之後才寫入，戳記會歸到錯誤的行。
- 因此需要在每個探針前後 flush stdout。這會改變程式的緩衝行為，但**不改變輸出內容**，要用差分測試驗證。

### 2.3 交付方式

目前 `session.js` 在程式結束後一次交付輸出。改為：每個步驟附帶「該步的輸出片段」與「該步的後狀態」，前端依目前停在的行顯示。

## 5. 風險

1. **cout 緩衝歸屬**：若 flush 方案不可行，輸出只能歸到「程式結束時」，功能會大打折扣。S0 必須先驗證。
2. **效能**：每步額外的戳記與 flush 會增加開銷。步數上限 20 萬筆、軌跡上限 24 MB，需實測是否接近上限。
3. **trace 可被偽造**：宿主戳記由宿主產生，但記錄內容仍是程式寫的。加入欄位後，驗證邏輯要明確區分宿主欄位與程式欄位。
4. **協定變動**：`session.js` 的交付順序（輸出在結束後）是現有契約，改動會影響 golden 測試與前端行為，需要明確更新。
5. **語意的歧義**：呼叫行與 return 行的「後狀態」規則複雜，容易在邊界情況出錯，需要用 7 個錯誤程式與既有教案一起驗證。
6. **與記憶體功能的邊界**：本計畫只處理純量與輸出，不處理結構與堆積。若之後要做記憶體圖，會沿用本計畫的後狀態機制，但需另案。
