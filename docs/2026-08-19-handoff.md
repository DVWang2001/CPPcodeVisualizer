## 1. 測試環境（不讀這段會浪費你很多時間）

**開發機是 Windows，Python 測試在本機完全跑不起來**：`jail_manager` 會 `import pwd`（Unix only），
且本機沒有可用的 Docker daemon。使用者要求**所有測試都在正式機上跑**。

```bash
bash .superpowers/sdd/2026-08-19-dp-table-quiz/pytest-remote.sh tests/xxx.py -v
bash .superpowers/sdd/2026-08-19-dp-table-quiz/node-remote.sh jest [檔案]
bash .superpowers/sdd/2026-08-19-dp-table-quiz/node-remote.sh tsc --noEmit
```

三個設計決定：一律掛 **`nice -n 19`**（正式機同時在服務學生，測試必須隱形）；用**拋棄式容器 +
獨立 checkout `~/dp-quiz-work`**，絕不進線上容器；**不需要先 commit 或 push**（腳本 tar 未提交的
工作目錄，TDD 紅燈階段照常）。

現況：**jest 460/460 通過**，`gdbgui/` 自身 tsc 零錯誤（`node_modules/@types/babel__traverse`
的錯誤是環境既有的，與程式碼無關）。Python 測試在拋棄式容器裡有 **34 個既有失敗**（sandbox
隔離測試缺 compose 的 seccomp 設定），改動前後完全相同，不是回歸。

⚠️ **Windows 檔名不分大小寫**。建測試檔前先確認同名檔案是否存在——我曾用

## 2. 這一輪做了什麼（`1aed331..487ada6`，9 個 commit）

```
487ada6 填表格改成一頁看完，不再橫向捲動
358d29c 續播指令是在閘門檢查那裡被丟掉的
4277365 收卷後續播——先前修錯了變數，也漏了真正執行
ae2b41f 重新執行開新課（這次連收課的收尾也擋住）
e7681cd 開課時載著同一個版本就不要重載教案
fe9cf08 移除「重新執行開新課」的鉤子，它會殺掉剛啟動的程式
6aa82ec 即時課堂面板搬進側欄
a69074b 重新執行就開一堂新課
2822018 收卷後播放停在原地
```

### 面板搬進側欄（`6aa82ec`）
橫幅以前佔程式碼上方約 250px 整堂課，而 QR 只有開場 30 秒有用。改成側欄的掛載點
（`RightSidebar.tsx` 的 `<div id="live-quiz-slot" />`），由 `SourceCode.tsx` 用
`ReactDOM.createPortal` 畫進去——props 全是 SourceCode 的方法，用 portal 就不必把狀態往上提。
工具列的按鈕改成**預設勾選的勾選框**（`data-testid="live-quiz-open"` 沿用，那是 e2e 契約）。
**勾選 ≠ 開課**：勾選只讓面板顯示，開課由「重新執行」觸發。

### 重新執行＝開一堂新課（`a69074b` → `fe9cf08` 移除 → `e7681cd` + `ae2b41f` 修好後接回）
使用者明確選擇「每次 restart 都開新課堂」，代價是已加入的學生被踢出、必須重掃 QR，
所以開好之後會自動彈出 QR 放大層。

**這個功能踩過一次大雷**：鉤子掛在 `inferior_program_starting`，而開課／收課的副作用**包含
重載教案**，等於把原始碼與 binary 從剛啟動的 inferior 底下抽走 → `The program is not being run.`
兩道守衛才讓它能待在那個位置，**動它們之前先想清楚**：

* `lessonVersion.needsLessonVersionReload()` —— 載著同一版就只上鎖不重載
* `LiveQuizPanel` 的 `restartingRef` —— 換課途中跳過 `restoreLatest`（收課的收尾）

### 收卷後自動續播（`2822018` → `4277365` → `358d29c`）
**這個功能我修了三次，前兩次都在單元測試綠燈的情況下宣告修好，兩次都是錯的。**

* 錯誤一：寄放 `store.autoplay_pending_command`。那個槽**只有使用者暫停時**才會被寫入，
  題目觸發時是空的。
* 錯誤二：寄放 `_gdbgui_tts_playing.autoplayCommand`。那屬於**上一行**的語音。
* 真正的遺失點：**`gdbgui_execute_autoplay_command` 的閘門檢查**。題目開著時該行的 TTS 仍會
  播完，播完呼叫它執行 `[next]`，而它看到閘門關著就 `return`——指令無聲消失。三個檢查點
  （進入時、延遲後、動畫 barrier 後）現在都改成 `lessonQuizRuntime.stashAutoplay(command)`，
  `questionClosed` 時交還。

⚠️ **使用者尚未確認這個修正在真實環境有效。**

## 4. 正式機的硬限制與實測數字（別重新猜）

| 項目 | 值 |
| --- | --- |
| 編譯一次 | **CPU 0.62 s**，峰值 RSS 79 MB |
| GDB 單步一次 | 0.015 s |
| GDB 常駐 / 學生程式 | 43 MB / 3 MB |
| 伺服器閒置 | 0.00% CPU / 48 MB |
| 全站 JS | 14.4 MB → gzip 3.5 MB |

**除錯幾乎免費，成本全在編譯。** 40 人同時開始 = 25 CPU 秒 + 3.1 GB 瞬間需求。

已上線：編譯 `BoundedSemaphore(4)` + **`nice -n 19`**（實測 4 個編譯讓單步從 17ms 惡化到 77ms，
掛 nice 回到 15ms；`chrt --batch` **無效**，SCHED_BATCH 只改搶佔粒度不改 CFS 權重）。
`Compress(app)` 曾對**所有 JS 空轉**（Flask-Compress 1.10.1 預設只認 `application/javascript`，
而 IANA/Werkzeug 已改成 `text/javascript`）——修好後點進教案從兩分鐘降到二十幾秒。

**下一步效益最大的是成品快取**（未做）：40 人開同一份教案 = 位元組相同的原始碼，
用 SHA256 當 key 編一次、其餘複製執行檔，25 CPU 秒 → 0.6 秒，比多買 4 倍硬體有效。
⚠️ 快取只能由**伺服器**（單一 uid）寫，學生 session 帳號只能讀。**不要用 ccache**——
它需要所有 session 可寫的共用目錄，惡意學生能污染快取讓別人執行他的程式。

其他：**HTTPS 做不了**（校方防火牆丟棄 inbound 80/443，Let's Encrypt 三種驗證全不通；
Cloudflare Tunnel 是唯一不需學校配合的路，使用者決定先不做，**現況學生密碼明文過網路**）。
**不要順手 `ufw enable`**（目前 inactive，沒先 `allow 22` 會把自己鎖在門外）。
`.env` 是必要的（`MOBILE_JOIN_BASE_URL` 沒設會拒絕啟動），已在 `.gitignore`。

## 5. 唯一未解決的 bug：手機填表看不到自己打的數字

**症狀**：學生打字時格子始終空白；送出後也看不到自己的作答與對錯標記。

**已排除（每條都有實證，不要重查）**：

* **伺服器正常。** `live_quiz_responses.answer_json` 實際存下 40 格非空資料（11/40 答對）；
  `guest_state()` 的 payload 完整：`rows:5, cols:8, answer:[["0","0",...]]`。
  socket 與 HTTP 走同一個 `guest_state`，沒有欄位落差。
* **元件邏輯正常。** `TableAnswerGrid.jest.ts` 既有六條測試全綠，涵蓋「打字要顯示」
  「收卷後標對錯」「server 作答取代草稿」。
* **不是版面／CSS 寬度。** 截圖確認 5×8 一頁顯示、標題列樣式有套用（表示 CSS 有載入）。
* **不是「值在但看不見」。** 手機長按格子只出現「全部選取」、選不到那個字元
  ——**input 的 DOM value 是空的**。

**收斂到的那一行**（`gdbgui/src/js/TableAnswerGrid.tsx`）：

```tsx
const displayedValues = question.answer || values;
```

打字更新 `values`（所以送出的資料正確），畫面顯示 `question.answer`。
症狀只有在「**送出前** `question.answer` 就已經是非 null 的空字串陣列」時才成立。

**下一步該查**：`question.answer` 為何在送出前是 truthy。候選是
`studentQuizState.ts:155` 的 `tableValues(raw.answer, rows, cols)`，或 `markSubmitted`
之後的快照把 `answer` 填成空陣列再推回元件。

**最快的取證方式**：學生頁面**不需要登入**（掃 QR 輸暱稱即可）。用瀏覽器開加入連結、
自己打字，看 React DevTools 裡 `question.answer` 的實際值。這個 bug 已經推翻三輪程式碼推理，
**不要再靠讀原始碼猜**。

## 8. 未解決：換課時舊課堂的 ended 事件會關掉新課堂的 runtime（2026-08-20）

**症狀**：按 Run 建立新課堂後，播放到綁定行時**題目不會開**，而畫面上一切看起來正常。
e2e `zz_live_quiz.spec.ts` 兩條測試因此紅（學生端等不到題目）。
`dp-table-quiz.spec.ts` 走同一條路卻通過——所以它是**時序相關**的，不是必然發生。

**機制（已確認）**：`restartSession` 先 `endLiveSession(舊)` 再 `createLiveSession(新)` →
`connect(新)` 會 `lessonQuizRuntime.activate(新)`。舊課堂的 `ended` 事件經 socket 晚一步
回來，`finishEnded` 照常收尾就 `deactivate()` 掉剛啟用的 runtime。

**試過但沒生效的三種修法**（不要重試同樣的東西）：

1. `restartingRef` 旗標——只擋住了 `restoreLatest`，擋不到 deactivate。
2. `finishEnded` 開頭以 `ended.id !== sessionRef.current.id` 提早 return。
3. 在 `connect()` 內同步 `sessionRef.current = current`，不等下一次 render。

三種都試過之後測試仍紅，**代表 deactivate 的來源不是 finishEnded**。下一步應該先確認
是誰呼叫了 `lessonQuizRuntime.deactivate()`——在 `deactivate` 內加一行 stack trace 印出來
比繼續猜快得多。候選：`activate()` 自己開頭就會呼叫 `this.deactivate()`；或 socket 的
`syncSession` 路徑。

**測試狀態**：`gdbgui/src/js/tests/LiveQuizPanel.jest.ts` 裡那條已標 `test.skip` 並註明
是產品 bug 而非不穩定測試。標 skip 是為了讓其餘 463 條仍是可用的訊號，**不是**讓問題消失。

**對課堂的實際影響**：按 Run 之後題目有機會不開。發生時的 workaround 是再按一次 Run
（重新建立課堂），但那會把已加入的學生再踢一次。**上課前務必自己走一遍完整流程。**
